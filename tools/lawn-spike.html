1 What the board holds today

Before drawing a single option, I loaded the running game (garden on :8899, a fresh tab), unlocked plots and levels through the dev tools, and pulled three creatures into the yard through the console the same dev sheet already exposes (Game.checkCritters() — no game file was edited). This is what I found, and it is the ground truth for the whole spike: the yard band is the ONLY strip of visible grass in the entire layout. The 3×3 board itself is soil, not lawn. Doc 52's own diagram draws "the lawn" as if it were a spare surface next to the garden; on the real screen there is no such spare surface — there is only this one band, already spoken for.

2 Everything on the grass — the current ruling

Perks stand on the garden itself, on the same band the creatures already stand on — there is nowhere else that reads as "grass." Drawn honestly, including doc 52's own worst case: five perks, up to four tending creatures, the two existing floating buttons, all sharing 350px of width.

3 A lawn button — the owner's idea

One object stands in for the whole system. Tapping it opens a picker with multiple slots inside; the board shows little or nothing of what you have equipped.

This sits in direct tension with the standing 2026-09-26 ruling in doc 52: "The lawn is not a screen and has no door. Spots live on the garden board; tapping an empty spot opens a picker, exactly as tapping an empty plot opens seeds today." That ruling was made after judging tree-spike's frame 6, which drew the lawn as a destination and got told off for it. The owner's newer idea reopens exactly that question from a different angle — not "should the lawn be a screen," but "should the board show the slots at all." I'm drawing it because he asked me to and because that's what this gate is for, but the collision is real and I am not resolving it by drawing it prettily. If approach 3 is chosen, doc 52's "no door" line needs a deliberate rewrite, not a quiet one.

4 A hybrid — quiet objects, a button to manage

The build stays visible at a glance, at a much lower visual weight than approach 2 — small, unlabelled tokens rather than full icon-and-name objects. Changing what's equipped goes through one picker rather than per-spot pickers.

5 A fourth option this drawing suggested — the perk rail

Suggested by section 1's own finding: doc 08 already reserves a row for exactly this kind of small, glanceable status information — "boost countdowns... row 3, reserved — hidden if short." Perks as a row of small chips at the top of the screen cost the grass nothing at all, because they never touch it.

6 The creature question, directly

Nobody has ruled this. Creatures occupy tending slots (HABITAT_SLOT_LEVELS = [1, 5, 10, 16], doc 52 §6) and are a whole separate system from perks — feeding, sleeping, keepsakes, pairs, stars. Two readings, drawn at the same crowded density as section 2's worst case so the comparison is honest.
