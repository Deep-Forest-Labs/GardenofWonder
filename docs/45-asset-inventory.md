# Asset inventory

Everything the Unity build has to draw, in two parts: the **icon manifest**, which is a set of
real files you can lift, and the **full art inventory**, which is everything else — parametric
drawing code that has to be recreated rather than imported.

## Licence

**All art in this project is original first-party work, and the Unity team may lift the SVGs
directly.** Nothing here is stock, licensed, or traced. The docs record this in two places:
[05-art-direction.md](05-art-direction.md) states the rule that every visual is inline SVG built
in JavaScript or CSS, and [22-creatures.md](22-creatures.md) records the deliberate decision
behind the creature designs — the silhouette language of the kodama archetype is borrowed, the
drawings are not, *because the game ships commercially*. That call is in
[10-decision-log.md](10-decision-log.md) with its reasoning.

Two things in the repository are **not** covered by that sentence, and neither is in this
inventory:

- **The Baloo 2 web font**, loaded from Google Fonts. It is the project's only external resource
  and it carries its own licence — source it yourself for the Unity build rather than copying it
  out of here. The game is designed to degrade gracefully without it.
- **`art/announcements/`**, the What's New art. It is first-party but **owner-supplied**, not
  generated in this repo, and re-exporting it is the owner's call. See the exception list in
  [09-conventions.md](09-conventions.md).

# Part 1 — The icon manifest

Every icon in the game, exported as a standalone `.svg` you can drop straight into Unity.
Regenerate the files and this table with:

```bash
node tools/export-icons.js
```

The exports live in [`art/exports/icons/`](../art/exports/icons/) and are a **mirror of
`icons.js`, never a source** — edit an icon in `icons.js` and run the command again. SVG is text,
so this needs no exception to the no-binary-assets rule in
[09-conventions.md](09-conventions.md).

Each file is the exact markup the game draws, plus an `xmlns` and a `width`/`height` taken from
its `viewBox` so the file has an intrinsic size when opened on its own. Every one is
self-contained: no `<use>`, no external references, and no CSS custom properties — a glyph that
reached for a variable declared in `style.css` would paint nothing in a file by itself, so the
exporter refuses to write one.

The script asserts that the number of files written equals the number of icons in the registry.
That assertion is the point of it: `icons.js` builds its registry in two parts — an object
literal and a later `Object.assign` — so an icon added to the second block is exactly the kind of
thing a hand-maintained list loses silently.

**The "Used by" column is scanned, not written by hand.** An icon is asked for in four different
shapes — `Icons.get('coin')`, the `ico('coin')` short helper, a `data-icon="coin"` attribute
hydrated later, and an `icon:` field on a data row reached at runtime through the dynamic
`Icons.get(d.icon)` form. That last one names no icon at the call site, so the data row is the
only evidence it is used at all, and the table attributes it to the table that holds it.

## The six things most likely to cost you a rebuild

**Growth is one attribute, not three sprites.** A flower has 19 SVG strings, not 57. Stages
1 and 2 are pure CSS transforms on the same markup — stem `scaleY` from the base, head scale
from `(50, 44)`, petal-group scale at stage 2 only. Build one prefab driven by a single 0–1
float. The project's own performance rule says it plainly: growth is one attribute flip, not
new SVG.

**Rarity and mutations are never flower variants.** Nobody draws a "rare daisy". Rarity is
rolled at *harvest* and shows as a burst plus a ring left on the empty plot; a mutation is a
recolouring of the plot *around* an unchanged bloom. Recreate both as a per-plot decal or
shader layer taking one or two colours — `19 × 4 = 76` flower variants is the wrong build and
it is the obvious wrong build. The difference that matters mechanically: a mutation is visible
**the moment it lands** and stays until harvest, while a rarity is only revealed at the end.

**Backdrops are drawn at the size the room actually measures.** `Fall.scene()` and
`Meadow.scene()` take a width and a height and compose against them; they are not fixed
artboards, which is why neither has a sample file here. This is the one lesson both files
record in their own headers: a composition made at 390×844 and rendered with
`preserveAspectRatio="slice"` does **not** crop, it **scales** — at 1440 wide the grass became
a hedge and a tree filled a third of the screen, and that shipped once.

**A season's scene has two visible bands, not one canvas.** The board covers roughly y 25%–70%
on a phone, so anything composed into the middle is drawn and then hidden. Compose into the top
band — sky, sun and moon, stars, clouds, hills, hedge line — and the bottom one — ground,
texture, props — and check by looking rather than by reading coordinates.

**Decor is bought and counted, but never drawn in the world.** Tracing every consumer of
`state.decor`: it is written by `buyDecor()` and by the level-19 grant, and read by exactly one
function, `decorCount(id)`, which the shop card uses for its "Owned ×N" caption. Nothing places
a gnome in the garden. Four pieces are content that exists; the placement feature does not.

**Card art is a pipeline, not an asset set.** There are 108 named cards across 12 sets, with
rarities, set tints, and the whole reveal and celebration staging — and **no real card art at
all**. Every slot is filled by one of nine placeholder motifs cycled by the card's index within
its set, so every set's card #1 is the same sprout on the same green disc. The slot mechanism
(`{icon, tint}` for the placeholder, `{src}` for a real image) is what you inherit;
[20-card-art-prompts.md](20-card-art-prompts.md) is the spec for filling it.

## The representative samples

Six files in [`art/exports/samples/`](../art/exports/samples/), one per class whose draw
function returns complete markup for a fixed viewBox, written by the same command as the icons:

```bash
node tools/export-icons.js
```

They exist so the house style can be opened rather than described. Each carries one small fix
**inside the file**, because none of these classes is quite standalone on its own:

- `flora.js` writes `fill="url(#gp-daisy)"` and keeps those gradients in a separate hidden
  `<svg>` that `injectDefs()` appends to the page. Exported raw, all nineteen blooms paint as
  **hollow outlines**. The exporter runs the game's own `injectDefs()` against a small DOM stub
  and keeps what it built, so the gradients in these files are the real ones and cannot drift
  from a hand-written copy.
- `critters.js` and `customers.js` draw **every state at once** and let CSS choose — a raw
  creature has open eyes, shut eyes and floating Zs all at the same time. One `<style>` rule
  picks the state.
- The Talking Flower's eyelids are full-height rectangles that `style.css` collapses with
  `transform: scaleY(0)`. Without that one line it exports **asleep**.

The two backdrops are exportable too, but deliberately have no sample, because any file would
be one arbitrary window size. Their recipes, both run cold in an empty Node `vm` sandbox:

```js
// Fall's backdrop — fall.js needs no stub at all
const ctx = vm.createContext({});
vm.runInContext(fs.readFileSync('fall.js', 'utf8'), ctx);
vm.runInContext("Fall.scene({ width: 390, height: 844, dockHeight: 96, sky: 'sun' })", ctx);

// The meadow's backdrop — same shape
vm.runInContext(fs.readFileSync('meadow.js', 'utf8'), ctx);
vm.runInContext("Meadow.scene({ width: 390, height: 844, dockHeight: 96, sky: 'sun' })", ctx);
```

`Meadow.cobbleFloor(i)` for `i` in 0–7 returns the eight cobble floors the same way. None of
those files touches `document`, `window` or `location` at module scope, which is what makes
them loadable outside a browser at all — a property worth keeping.

## What has no draw function

Rarity, mutations, Summer's soil, the twelve scenery bands and the eleven weather layers have
**no function to call**. Every pixel is a CSS gradient, a `box-shadow` or a blend mode on an
empty `<div>`, so there is nothing to export and the source is the specification.
[05-art-direction.md](05-art-direction.md) holds the material recipe those are built from, and
the weather layers in particular carry a constraint worth reading before reimplementing them:
the layer may **never** take a `z-index`, because a stacking context is an isolated blending
group and every `multiply` inside it would then blend against transparency instead of the sky.
